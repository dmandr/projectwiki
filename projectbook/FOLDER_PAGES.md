# Страницы каталогов: `.index.md`

Дата: 2026-10-25. Статус: реализация и локальная проверка. Cloud deployment приостановлен по запросу пользователя.

## Назначение

Каталог должен одновременно быть узлом дерева и полноценной редактируемой страницей. Это убирает необходимость показывать рядом отдельную статью «Двигатель» и каталог с её подстраницами.

Для содержимого каталога используем служебный файл `.index.md` внутри него. Окончательное зарезервированное имя — `.index.md`, по уточнению пользователя от 2026-10-25. Это обычное Markdown-содержимое страницы каталога.

```text
boat/
  .index.md                 ← «Устройство лодки»
  engine/
    .index.md               ← «Двигатель»
    maintenance.md          ← обычная подстраница
    cooling.md              ← обычная подстраница
```

Файл хранится и версионируется в Git вместе с документами. В дереве он не отображается отдельным элементом: его содержимое представляет сам каталог. Это специальное поддерживаемое системой исключение среди скрытых файлов, а не возможность создавать произвольные dot-файлы через UI.

## Название и путь

- Отображаемое название каталога берётся из первого заголовка H1 в `.index.md`.
- Название не обязано совпадать с физическим именем каталога. Например, путь `boat/engine/` может иметь заголовок «Двигатель Volvo Penta».
- Редактирование Title меняет H1, но не путь каталога и не имя `.index.md`.
- Move меняет путь каталога вместе с его содержимым; заголовок остаётся прежним, если пользователь отдельно его не изменил.
- Если заголовка нет, используется существующее правило получения названия из пути. При создании новой страницы заголовок создаётся сразу.

## Создание и содержимое по умолчанию

Создание страницы каталога использует те же правила ввода названия, выбора языка и формирования пути, что и создание обычной страницы. В новом каталоге система создаёт `.index.md` с двумя элементами:

1. Заголовок H1 с введённым названием.
2. Динамический блок «Подстраницы», показывающий непосредственное содержимое этого каталога.

Блок хранится в Markdown как специальная вставка, а не как вручную скопированный список ссылок. Синтаксис: `[Pages](#projectbook-pages)` отдельным абзацем. В просмотре он заменяется актуальным списком; в визуальном редакторе остаётся перемещаемым и удаляемым блоком-ссылкой. HTML-комментарии не нужны.

Блок отражает актуальные подстраницы и их порядок в дереве: учитывает `.order`, а при его отсутствии использует обычную сортировку. Сам `.index.md`, `.order` и остальные служебные файлы в список не попадают. Если подстраниц нет, блок не выводит пустую таблицу или заглушку: остаётся заголовок страницы.

## Редактирование и просмотр

Страница каталога редактируется обычным редактором в визуальном и Markdown-режимах. В неё можно добавлять текст, изображения, таблицы, TODO и другие поддерживаемые конструкции.

Блок подстраниц можно переместить или удалить вручную. После удаления система не добавляет его обратно и не рисует дополнительный обязательный список рядом с содержимым. Если оставить только заголовок, при просмотре виден только заголовок. Подстраницы при этом сохраняются и доступны через дерево.

Из любого такого узла можно создавать и редактировать подстраницы. Изменения `.index.md` должны обновлять содержимое справа и название узла в дереве через обычный механизм сохранения и обновления представления.

## Поведение дерева

- Один каталог — один видимый узел с названием из `.index.md`.
- Выбор узла открывает его обзорную страницу.
- Стрелка раскрывает или сворачивает дочерние элементы; сохраняется согласованное поведение повторного клика без повторной загрузки уже открытой страницы.
- Содержимое страницы не ограничивается списком файлов: каталог может быть полноценной статьёй с подстраницами.

## Удаление

Удаление узла каталога или его обзорной страницы через интерфейс означает **удаление всего каталога**, включая `.index.md`, вложенные страницы, подкаталоги и находящиеся внутри файлы.

Перед этим обязательно показывается отдельное явное подтверждение, объясняющее, что удаляется всё поддерево, с названием и путём каталога. Рекомендуется также показывать число затронутых страниц и файлов. Это подтверждение **нельзя отключить в Settings**, независимо от настроек других подтверждений.

Без подтверждения операция не выполняется. После подтверждения удаление фиксируется одним Git-коммитом через общий механизм записи с проверкой версии. Соответствующая запись удаляется из `.order` родительского каталога.

Корзины в этом сценарии нет: файлы исчезают из текущей версии книги. Однако история Git сохраняется, поэтому удаление не означает стирание предыдущих версий из репозитория.

Чтобы очистить обзорную страницу, сохранив подстраницы, нужно редактировать её содержимое, а не использовать Delete. Удаление блока «Подстраницы» также не удаляет никаких документов.

## Совместимость и границы следующей реализации

- Обычные Markdown-страницы остаются обычными страницами; изменение не требует превращать каждый документ в каталог.
- Для существующих каталогов без `.index.md` требуется отдельный шаг перехода. Предложение: до создания файла сохранять нынешний обзор каталога, а при явном создании его страницы добавлять заголовок и блок подстраниц. Простое открытие не должно создавать файлы или коммиты.
- При переносе существующей статьи в `.index.md` нужно сохранить содержимое и исправить ссылки через общий механизм Move; порядок внутри каталога сохраняется.
- Нельзя предоставлять обход обязательного подтверждения удаления через альтернативную кнопку. Поведение удаления через MCP/API следует согласовать при реализации: обычный запрос удаления одного файла не должен неожиданно удалять поддерево.
- Удаление корня всей книги не следует автоматически выводить из правил удаления вложенного каталога; это отдельная административная операция.

## Критерии проверки

- В дереве нет пары «обзорная статья + одноимённый каталог» и отдельной строки `.index.md`.
- Название узла соответствует H1, даже если физический путь называется иначе.
- Новая страница каталога содержит заголовок и динамический блок подстраниц.
- Удаление блока сохраняется после повторного открытия; автоматический список больше не появляется.
- Вложенные страницы доступны и редактируются независимо от наличия блока.
- Title не меняет путь; Move переносит всё поддерево с его внутренним порядком.
- Отмена удаления ничего не меняет; подтверждение нельзя отключить.
- Подтверждённое удаление убирает всё поддерево одним коммитом, очищая родительский `.order`.
