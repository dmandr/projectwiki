# Project Book Manager

Небольшая Docker-админка и общий MCP для нескольких книг. Отдельный проект внутри исходников; он использует существующий образ Project Book и не меняет текущие инсталляции.

## Работа с книгами

В **People** ведётся общий справочник (имя и email, до 50 записей). Запись сама по себе не выдаёт доступ и не создаёт учётную запись Cloudflare. Пользователь входит через настроенный в Cloudflare способ входа. Email уникален; удалить запись из справочника можно после снятия доступа ко всем её активным книгам. Лимит справочника не показывает оставшиеся места тарифа Cloudflare: другие приложения аккаунта могут использовать те же места.

В **New book** укажите название и Git-репозиторий (`owner/repository`, `https://…` или `git@host:path`). При настроенной интеграции Cloudflare выберите короткое имя адреса `имя.dmandr.net` и людей галочками из справочника; полный произвольный домен не принимается. Без интеграции сохраняется ручной HTTPS-адрес. По умолчанию включён semantic search. Manager:

1. Создаёт отдельные Docker volumes, клонирует репозиторий и определяет его текущую ветку. В пустом репозитории создаёт Home и первый локальный commit.
2. Запускает контейнер книги; при включённом поиске — также RAG и Qdrant. Индексирование запускает штатный worker RAG, состояние видно в карточке.
3. Показывает постоянный локальный порт вида `127.0.0.1:23456`. Он сохраняется при перезапуске контейнера. Книга становится Ready после успешного MCP-запроса.
4. Подключает книгу к общему `/mcp`. В клиенте не нужна отдельная OAuth-настройка каждой книги.

Создание идёт фоном; UI отвечает сразу. Clone, первый download модели и индексирование могут занимать существенно больше нескольких секунд. При включённой интеграции DNS/Access/маршрут создаются автоматически; при подключённом GitHub App отсутствующий репозиторий создаётся автоматически как private. Без GitHub App репозиторий должен уже существовать.

**Remove** требует ввести название книги. Manager блокирует новые MCP-вызовы к книге, дожидается активного вызова, останавливает web/RAG, делает `git add -A`, commit при наличии изменений, обычный push текущей ветки и проверяет SHA удалённой ветки. Локальные Raw Notes включаются принудительно, даже если обычная синхронизация заметок отключена. Только после успешной проверки удаляются контейнеры книги, RAG и Qdrant. Force push отсутствует. Ошибка push/конфликт оставляет контейнер книги остановленным и данные на месте; **Retry** повторяет сохранение и удаление после устранения причины.

Volumes не удаляются: сохраняются книга, настройки, неотслеживаемые служебные файлы, модели и индекс. Скрытые ignored-файлы за пределами Raw Notes автоматически не публикуются в Git. Незагруженные файлы и браузерные черновики в удаление не входят. Git remote не удаляется. При автоматической интеграции после успешного push, но до освобождения порта, удаляются только принадлежащие книге DNS и маршрут, политика отвязывается от общего MCP. Access-приложение и политика остаются как защита старого адреса; повторное использование имени требует отдельной проверки и ручной очистки в Cloudflare. Ручные установки Cloudflare/DNS не меняют. Восстановление volumes описано ниже.

## Быстрый локальный запуск

Из корня репозитория приложения:

```sh
docker build -t projectwiki:local -f projectbook/Dockerfile .
docker build -t projectbook-rag:local projectbook/rag
cd projectbook/manager
MANAGER_AUTH=local docker compose up -d --build
```

Админка: `http://127.0.0.1:8070`. MCP: `http://127.0.0.1:8071/mcp`.
Образы книг задаются через `BOOK_IMAGE`, `RAG_IMAGE`, `QDRANT_IMAGE`; на сервере используйте закреплённые версии для его архитектуры. Если semantic search отключён в форме, образ RAG не требуется. Отсутствующий образ приводит к явной ошибке установки; после загрузки/сборки нажмите Retry. Manager не собирает исходники и не выполняет пользовательские shell-команды.

`MANAGER_AUTH=local` предназначен только для закрытого локального стенда. Все опубликованные Docker-порты привязаны к loopback. Не публикуйте этот режим через туннель. Файл `.env` исключён из Git; пример — `.env.example`.

## Cloudflare и сервер

1. Разверните на Docker-хосте образы и Manager. Скопируйте `.env.example` в `.env`, задайте `MANAGER_AUTH=cloudflare`, `ACCESS_ISSUER`, публичные URL и два audience из Access applications. Без этих параметров Cloudflare-режим откажется стартовать.
2. Направьте домен админки на `http://127.0.0.1:8070` и защитите Cloudflare Access политикой **только для администраторов**.
3. Направьте домен MCP на `http://127.0.0.1:8071`; для `/mcp` настройте отдельное Access-приложение с **Managed OAuth** и нужной политикой пользователей. `MCP_PUBLIC_URL` должен содержать полный внешний URL с `/mcp`. При необходимости оба сервиса можно разместить на одном домене с маршрутизацией по пути; два домена проще конфигурировать.
4. Manager проверяет подпись Access JWT, issuer, audience и срок действия. MCP audience не даёт доступ к админке. Простой email-заголовок не считается авторизацией. OAuth discovery и внешний challenge предоставляет Cloudflare.
5. После создания книги направьте её выбранный hostname на выданный Manager порт и создайте обычное Cloudflare Access приложение для Web UI. Общий MCP работает через внутреннюю Docker-сеть независимо от этого домена.

Эти адреса `127.0.0.1` относятся к Docker-хосту. Для cloudflared в контейнере используйте доступный ему host gateway/host networking, а не loopback самого cloudflared. Не открывайте порты книг в Интернет в обход Cloudflare.

Текущий `boatwiki.dmandr.net/mcp` не меняется этим проектом. Для общего Manager выбран `pb.dmandr.net`: админка на `/`, MCP на `/mcp`. `compose.cloud.yaml` добавляет nginx на `127.0.0.1:8093`, который направляет эти запросы на отдельные слушатели Manager. Запуск: `docker compose -f compose.yaml -f compose.cloud.yaml up -d --no-build --wait`.

## Git credentials

Новая интеграция [GitHub OAuth](GITHUB.md) добавляет Connect GitHub, проверку прав и создание отсутствующего private-репозитория. Проверена на локальном стенде `http://127.0.0.1:8074` и включена на `https://pb.dmandr.net` в релизе `projectbook-manager:github-20261028`. Использует короткосрочные GitHub App user tokens с автоматическим refresh. Ниже — прежний ручной способ для установок без GitHub App.

Настройка автоматического Cloudflare и токена с минимальными правами описана в [CLOUDFLARE.md](CLOUDFLARE.md). 28 октября 2026 облачная установка обновлена до `projectbook-manager:cloudflare-20261028`: справочник людей, выбор доступа и автоматическая публикация включены. Бессрочный токен ограничен IP сервера и тремя указанными разрешениями. Прошли 35 тестов в серверном образе и проверка настоящего API Cloudflare с созданием и очисткой временных ресурсов. GitHub credentials затем подключены через GitHub App OAuth, см. [GITHUB.md](GITHUB.md).

Credentials хранятся в отдельном volume `projectbook-manager-git`, вне Git книги и реестра. В UI и URL репозитория токены не принимаются. Один раз установите один из вариантов:

- SSH: `id_ed25519` с доступом к нужным репозиториям и заранее проверенный `known_hosts`. Отключения проверки host key нет.
- HTTPS: `https-token` — файл с токеном с правами clone/push необходимых репозиториев. Credential helper выдаёт его только HTTPS-хостам из `GIT_HOSTS` (по умолчанию `github.com`). Не передавайте токен через командную строку или tracked compose-файлы.
- Для собственного Git с частным CA можно положить `ca.crt` в тот же volume. TLS-проверка остаётся включённой.

Переносить файлы можно через временный контейнер с этим volume и `docker cp`. Файлы должны читаться root внутри Git helper; private key — mode 0600. Не монтируйте весь домашний `.ssh` или GitHub credentials пользователя. При необходимости расширьте `GIT_HOSTS` явным перечнем через запятую.

Git helper — короткоживущий контейнер с volume **одной** книги и credentials read-only; Docker socket в него не передаётся. Remote hooks не запускаются; системные/global Git-настройки отключены. Cloudflare OAuth-токен не пересылается в Git. В режиме GitHub App только короткосрочный GitHub access token передаётся отдельному Git helper через stdin и tmpfs; контейнеры книг credentials не получают.

## Общий MCP и права

Поддерживается stateless Streamable HTTP: `initialize`, `ping`, `tools/list`, `tools/call`, `resources/list`, `resources/templates/list`, `resources/read`. Сервер возвращает JSON, а ответы downstream читает как JSON или SSE. Постоянный GET/SSE-сеанс не требуется. Идентификаторы ресурсов книги и вложений переписываются с book ID, в том числе внутри JSON-текста.

Начните с `list_books`. Все остальные инструменты требуют `book_id`; скрытого текущего проекта нет. Имена, схемы инструментов и fileParams берутся из доступных экземпляров. Установки должны использовать совместимые версии Project Book. После первой книги или добавления новых типов инструментов (например RAG) обновите список инструментов в клиенте. Обычное добавление книги той же версии не создаёт новых имён инструментов. Пакетная транзакция сразу через несколько книг не поддерживается.

Для автоматических установок сначала проверяется выбранный список людей каждой книги. В старом ручном режиме без интеграции политика Cloudflare по умолчанию допускает пользователя ко всем книгам шлюза. Дополнительно ограничить права можно, создав **вне Git**, в state volume, `/data/access.json`:

```json
{
  "default": {"read": [], "write": []},
  "books": {
    "ID_FROM_MANAGER": {
      "read": ["owner@example.com", "reader@example.com"],
      "write": ["owner@example.com"]
    }
  }
}
```

`*` допускает всех уже авторизованных Cloudflare-пользователей. Email указывается в нижнем регистре. Файл перечитывается на запрос; повреждённая конфигурация запрещает доступ. Права проверяются на discovery, каждый tool call и чтение ресурсов; запись требует и read, и write. Это **распределение прав по книгам**, а общий допуск остаётся в Cloudflare. Админка доступна только через отдельную admin policy; этот ACL касается MCP. Web UI каждой книги защищается своей Access policy и существующим режимом книги.

## Хранение, восстановление и границы

- `projectbook-manager-state`: `registry.json` (имена, Git URLs, порты, статусы, служебные MCP-токены) и необязательный `access.json`. Файлы реестра записываются атомарно с mode 0600. Резервируйте volume как секрет, вместе с Git credentials.
- Volumes/контейнеры книг имеют имена `pb-<owner-prefix>-<book-id>-<role>` и owner/book labels. Manager не останавливает и не удаляет чужие ресурсы.
- После перезапуска незавершённая операция становится ошибкой с Retry. Активный старый Git helper не запускается повторно; нужно дождаться его завершения.
- Для восстановления удалённой установки можно сначала создать новую из Git. Для полного восстановления старого локального содержимого используйте сохранённые book/settings volumes с обычным compose Project Book. Пример: `docker run --rm -v NAME-book:/book:ro alpine tar -C /book -czf - . > book-backup.tgz` (имя берётся из реестра/labels). Удалять volumes после проверки backup — отдельная ручная операция.
- Остановка Manager: `docker compose stop`. Она не останавливает книги. `docker compose down` также не удаляет управляемые книги; их сеть может остаться занятой. Для чистого выключения сначала удалите установки через UI либо остановите их контейнеры вручную. Не используйте `down -v` для обслуживания реестра.
- Manager имеет Docker socket, то есть административные полномочия на Docker-хосте. Поэтому admin policy должна быть узкой; книги не получают socket/credentials/state. MCP слушает отдельный порт и не имеет lifecycle-инструментов, но находится в том же доверенном процессе Manager. Для изоляции недоверенных арендаторов понадобится отдельный worker/шлюз и отдельные Docker-хосты/сети.
- Все backend-контейнеры находятся в общей служебной Docker-сети. Эта версия рассчитана на книги одного владельца. Каждый backend MCP защищён своим случайным токеном.
- В этой версии нет автоматического Git pull/push во время обычной работы, создания GitHub-репозиториев, импорта существующих установок, обновления образов установленных книг или очистки сохранённых volumes.
