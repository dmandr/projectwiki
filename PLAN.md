## 1. Навигация и оформление

Готовы: лёгкий индекс Git с обновлением по локальному commit, английский UI, свёрнутые по умолчанию каталоги, стрелки как в VS Code, список каталога справа и просмотр вложений. Общая компактная панель с иконками, хлебные крошки, единая History с выбором книги/документа и кнопки New document / New folder проверены на Docker-стенде и одобрены пользователем для commit без push. Метаданные каталогов, темы и изменение ширины панели пока не реализованы. Следующий этап — редактор и вложения — согласован и реализуется ниже.
- Постоянная левая панель: полное дерево каталогов, документов и вложений, раскрытие/сворачивание, выделение текущего элемента, сохранение раскрытых узлов.
- Нажатие на каталог открывает справа список содержимого с названием, типом и доступными метаданными (например, временем последнего изменения из Git).
- Нажатие на документ открывает просмотр; для изображений/PDF — подходящий просмотр или ссылка на файл.
- Кнопки создания документа и каталога. Git не хранит пустые каталоги: выбрать явный файл-маркер либо создавать каталог вместе с первым документом.
- Аккуратные светлая и тёмная темы, читаемая типографика, удобное изменение ширины панели и адаптация к узкому экрану. Избранное/закрепление и настраиваемая главная страница — последующее дополнение.
- Проверка: глубокие каталоги, кириллица и пробелы, переходы назад, создание, перезагрузка и прямые ссылки.

## 2. Редактор и вложения — ключевой этап

Реализовано и проверено на локальном стенде: отдельный экран MDXEditor без Ace, Visual/Markdown/Changes, вставка вложений, единый commit документа с файлами, проверка версии и браузерные черновики с файлами. Добавлено управление шириной изображений (проценты/пиксели) с явным HTML `<img width="23%">` внутри Markdown. По результатам пользовательской проверки исправлены редактируемое имя нового документа, скрытие панели картинки и переходы до/после неё. Пользователь разрешил commit этих исправлений, без push.
- Полноценно встроить MDXEditor с режимами «Визуально», «Markdown» и просмотром изменений; связать напрямую с сохранением без скрытого старого редактора.
- Drag and drop прямо в тело редактора: изображения, PDF и прочие документы, несколько файлов. Изображения показывать внутри текста, PDF/документы вставлять ссылкой или карточкой с доступным просмотром.
- Определить размещение вложений, уникальные имена, относительные ссылки, ограничения размера, прогресс, отмену и повторы при ошибках. Бинарные файлы сохранять в Git книги.
- Изменение документа и добавление вложений согласовать; отмена редактирования не должна оставлять случайные опубликованные изменения.
- Сохранить текст при сбоях сети; показать понятную ошибку/конфликт и возможность восстановить черновик. Проверять версию документа при сохранении.
- Проверить переключение режимов, undo/redo, вставку Markdown, списки, таблицы, ссылки, фото/PDF, отсутствие неожиданных изменений при открытии и сохранении. Определить поведение неподдерживаемого синтаксиса.
- Начать со штатного API расширений MDXEditor. Отдельный форк редактора пока не нужен.

### Заголовок и Move — проверено, одобрено для commit
- Создание связывает Title и предлагаемый путь в обе стороны; из имени с дефисами/подчёркиваниями получается читаемый Title. Create and edit записывает начальный H1 и открывает редактор. Несуществующий адрес требует подтверждения создания.
- Название из первого H1 используется в навигации и списках. При отсутствии H1 — читаемое имя файла; H1 добавляется при сохранении. Новые автоматически предложенные имена — lowercase ASCII с дефисами и транслитерацией кириллицы; существующие пути не переписываются.
- Клик по заголовку или Rename открывает поле на месте заголовка. Меняется первый H1 в Markdown, путь и URL сохраняются; Enter применяет, Escape отменяет, Save записывает документ.
- Отдельная кнопка Move открывает подтверждение полного пути. Перенос, текущие правки и вложения сохраняются одним действием; новые каталоги создаются автоматически.
- Пересчитываются относительные Markdown-ссылки и HTML src/href внутри документа. Входящие ссылки из других страниц пока не обновляются.
- Подтверждение неизменённого Title не переписывает Markdown и не помечает документ изменённым. Индикатор показывает наличие несохранённых изменений, включая возврат к исходному тексту через Undo.
- Развёрнуто локально; пользователь разрешил commit 24 октября после исправления проверки изменений. Push не выполняем.

## 3. TODO
- Кнопка создания задачи и собственный визуальный элемент с описанием и галочкой.
- Предлагаемый переносимый формат: `[TODO: Описание](Tasks/<id>.md)`. ID стабилен; подпись содержит описание, отдельный файл — метаданные. Окончательно согласовать источник истины для текста при нескольких упоминаниях.
- Режим Markdown показывает обычную ссылку; визуальный режим позволяет менять текст, сохраняя ID. HTML-комментарии не обязательны.
- Создание/правка задачи и документа — одно согласованное сохранение. Просмотр страницы не создаёт файлов.
- Общий список задач и переход к упоминанию. Различать выполнение, удаление задачи и удаление ссылки; определить копирование и дублирование.
- Проверить round-trip между режимами, повторные ссылки и конфликт изменений задачи.

## 4. MCP
- Чтение, поиск, дерево книги, доступ к вложениям; затем создание/правка документов и задач.
- Все записи через тот же механизм, что Web UI: проверка версии, согласование операций Git, понятный результат.
- Настроить доступ и границы разрешений; не предоставлять произвольный shell как инструмент работы с книгой.
- Проверить подключение агента и сценарий обновления тестового документа.

## 5. Следующие этапы
- Git-синхронизация: старт, ручной запрос, обновление перед чтением/редактированием с ограничением частоты, post-commit; работа без сети, статус pending/last sync, конфликты и UI сравнения/слияния. Проверка двумя независимыми clone.
- Черновики: автосохранение, восстановление, автор/хост, синхронизация черновиков без force push; согласовать формат отдельно.
- Мобильные входящие: текст, фото, аудио без ручного редактирования Markdown; устойчивое сохранение, повторная отправка, дальнейший разбор через MCP. Полный offline и расшифровка — отдельные функции.
- Авторизация и удалённый deployment: GitHub-вход и проверка доступа к книге либо локальный режим; защищённый HTTPS-домен, секреты вне Git. Права Git-сервера не становятся автоматически правами Web UI.

Каждый этап заканчивается работающим локальным deployment, проверкой и просмотром пользователем. Commit/push приложения — после подтверждения результата, не автоматически после выполнения плана.
