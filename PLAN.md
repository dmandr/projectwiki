Общая компактная панель с иконками, хлебные крошки, единая History с выбором книги/документа и кнопки New document / New folder проверены на Docker-стенде и одобрены пользователем для commit без push. Метаданные каталогов, темы и изменение ширины панели пока не реализованы. Следующий этап — редактор и вложения — согласован и реализуется ниже.

- Нажатие на каталог открывает справа список содержимого с названием, типом и доступными метаданными (например, временем последнего изменения из Git).
- Нажатие на документ открывает просмотр; для изображений/PDF — подходящий просмотр или ссылка на файл.
- Кнопки создания документа и каталога. Git не хранит пустые каталоги: выбрать явный файл-маркер либо создавать каталог вместе с первым документом.

Добавлено управление шириной изображений (проценты/пиксели) с явным HTML `<img width="23%">` внутри Markdown. По результатам пользовательской проверки исправлены редактируемое имя нового документа, скрытие панели картинки и переходы до/после неё. Пользователь разрешил commit этих исправлений, без push.
- Полноценно встроить MDXEditor с режимами «Визуально», «Markdown» и просмотром изменений; связать напрямую с сохранением без скрытого старого редактора.
- Drag and drop прямо в тело редактора: изображения, PDF и прочие документы, несколько файлов. Изображения показывать внутри текста, PDF/документы вставлять ссылкой или карточкой с доступным просмотром.

- Изменение документа и добавление вложений согласовать; отмена редактирования не должна оставлять случайные опубликованные изменения.
- Сохранить текст при сбоях сети; показать понятную ошибку/конфликт и возможность восстановить черновик. Проверять версию документа при сохранении.
- Проверить переключение режимов, undo/redo, вставку Markdown, списки, таблицы, ссылки, фото/PDF, отсутствие неожиданных изменений при открытии и сохранении. Определить поведение неподдерживаемого синтаксиса.
- Начать со штатного API расширений MDXEditor. Отдельный форк редактора пока не нужен.

### Заголовок и Move — проверено, одобрено для commit
- Создание связывает Title и предлагаемый путь в обе стороны; из имени с дефисами/подчёркиваниями получается читаемый Title. Create and edit записывает начальный H1 и открывает редактор. Несуществующий адрес требует подтверждения создания.
- Название из первого H1 используется в навигации и списках. При отсутствии H1 — читаемое имя файла; H1 добавляется при сохранении. Новые автоматически предложенные имена — lowercase ASCII с дефисами и транслитерацией кириллицы; существующие пути не переписываются.
- Клик по заголовку или Rename открывает поле на месте заголовка. Меняется первый H1 в Markdown, путь и URL сохраняются; Enter применяет, Escape отменяет, Save записывает документ.
- Отдельная кнопка Move открывает подтверждение полного пути. Перенос, текущие правки и вложения сохраняются одним действием; новые каталоги создаются автоматически.
- Пересчитываются относительные Markdown-ссылки и HTML src/href внутри документа. Входящие ссылки из других страниц пока не обновляются.
- Подтверждение неизменённого Title не переписывает Markdown и не помечает документ изменённым. Индикатор показывает наличие несохранённых изменений, включая возврат к исходному тексту через Undo.
- Развёрнуто локально; пользователь разрешил commit 24 октября после исправления проверки изменений. Push не выполняем.

### Печать страницы — на стенде, commit `fca1be00`

## 3. MCP — чтение, память и редактирование закоммичены

Цель: обсуждать книгу с агентом, находить и читать материалы, исследовать историю, создавать и редактировать документы без ручной работы с файловой системой хоста. Первый этап реализован 24 октября: `/mcp` в текущем контейнере, официальный Ruby SDK 1.8.1, карта/resource, дерево, Markdown-чтение и поиск, история/diff, а также чтение и сохранение памяти агента. Инструкции подключения и ограничения — в [README](projectbook/README.md#mcp-book-access-and-durable-agent-memory). Чтение/память: `52fd5874`; запись документов: `59eb67d8`. Оба этапа отправлены в origin по подтверждению пользователя. RAG закоммичен как `2fbc27ed`, настройки — `42ba1e68`, без push; подключение основного экземпляра и PDF API реализованы и проверены, ожидают пользовательской приёмки без коммита.

### Реализованное редактирование через MCP
- `save_document`: создание и полная замена Markdown; `edit_document`: точечные уникальные замены.
- Обязательный `expected_version` — blob SHA из чтения; пустой только для создания нового пути.
- По умолчанию preview/diff без записи; `dry_run: false` повторно проверяет версию и сохраняет через общий с браузером сервис.
- Конфликт в обе стороны, no-op без лишнего коммита, защита локальных незакоммиченных файлов, отдельный флаг отключения записи.
- Move, вложения и пакетная правка нескольких документов через MCP остаются следующим расширением.

### Реализованная память агента
- По дополнительному запросу пользователя: summaries, выводы исследований и журналы задач сохраняются через MCP в `.projectbook/agent-memory/<uuid>.json` внутри книги. Содержимое заметки — Markdown; scope связывает её с документом, каталогом или всей книгой. Записи скрыты из дерева, но доступны через API и Git; это не отдельная граница конфиденциальности.
- `list_agent_notes` находит контекст из родительских областей и дочерние записи; `read_document` возвращает список релевантных заметок. `read_agent_note` читает полный результат работы. Нет автоматической записи каждого поискового запроса или скрытых рассуждений.
- Источники привязаны к blob SHA, изменения/перемещения/удаления помечают заметку устаревшей. Обновление требует версии заметки; повтор одинакового сохранения — no-op. Запись памяти использует общий с Web UI process-local lock и один локальный commit. Внешние Git-процессы этим lock не защищены.
- Проверено реальное HTTP-подключение официальным клиентом и восстановление памяти после переподключения. Поддержаны read-only настройка, необязательный Bearer token, ограничения Host/Origin и размеров. Стенд доступен только на loopback.
- Полноценные TODO, OCR, автоматическое обновление summaries и Git-синхронизация пока не реализованы. Запись документов, векторный поиск и PDF extraction уже работают. Ниже сохранён подробный целевой план; не все перечисленные расширения реализованы.

### RAG — реализованный поисковый слой
- Обсуждён стандартный вариант: фрагменты Markdown с путём/разделом/версией, embeddings и гибридный поиск по смыслу плюс точные термины. Используются локальные Qdrant и FastEmbed с multilingual MiniLM. Поддержка других моделей вынесена в низкий приоритет.
- Git остаётся источником документов и памяти. Векторный индекс — восстановимый кеш, не обязательная база книги; пересчёт по изменённым blob, удаление устаревших фрагментов. Не отправлять содержимое книги внешнему провайдеру без выбранной пользователем конфигурации.
- RAG выбирает ограниченный релевантный контекст, а не загружает всю книгу в модель. Карта книги и сохранённые summaries дополняют поиск. Буквальный поиск по Markdown остаётся доступным; дополнительный RAG даёт semantic/hybrid-поиск по Markdown и тексту PDF.

### Обзор и навигация
- `get_book_context`: компактная карта книги — назначение, основные разделы, краткое содержание, точки входа, число документов/вложений и Git revision. Для небольшой книги можно вернуть весь каталог; для большой — краткий обзор и явные ссылки на подробные разделы. Лимит размера и признак неполного ответа обязательны.
- `list_tree`: вся структура либо поддерево, с глубиной, постраничной выдачей, путями, Title, типом файла и ссылками на Web UI. Ответы должны относиться к явно указанной версии Git.
- `read_document`: исходный Markdown целиком либо по диапазону строк/разделу, оглавление, версия содержимого для сохранения, точный путь и URL. Разрешить чтение нескольких явно выбранных документов с общим лимитом ответа.
- `search_documents`: название, путь и содержимое, фильтры каталога/типа, выдержки с номерами строк, пагинация. Добавить ссылки на другие документы и обратные ссылки для исследования связанных материалов.
- `list_attachments` / `read_attachment`: метаданные, ограниченное чтение и ссылки на изображения/PDF/файлы. Извлечение текста из PDF и OCR — отдельные возможности; наличие бинарного файла в Git само по себе не делает его текст доступным поиску.

### Контекстный индекс
- Расширить существующий `NavigationIndex` (путь, Title, blob SHA) оглавлением, коротким извлечённым описанием, ссылками и Markdown-чекбоксами. Индекс строится локально и пересчитывает только изменённые файлы; удаление и Move тоже инвалидируют записи.
- Краткий первый абзац — извлечённый текст, а не обещание смыслового резюме. Авторские/агентские summaries хранятся отдельно от восстановимого индекса в обычных файлах книги с `source_path` и `source_blob_sha`. При изменении источника показывать устаревание; не выдавать старое резюме за актуальное.
- Не требовать LLM API, векторную базу или внешнюю индексацию для первой версии. Кеш восстанавливается из Git и не является источником истины. Явное перестроение индекса не создаёт коммиты документов.
- Предоставить карту как MCP resource и как tool: клиент сам выбирает, какие resources добавлять в контекст, автоматическая загрузка всего индекса не гарантируется. Описание сервера рекомендует начать с карты книги. Содержимое книги остаётся данными, а не системными инструкциями агента.

### История и редактирование
- `get_history`: история книги или документа, фильтры по датам/пути и пагинация. `read_revision` и `get_diff`: чтение старой версии и сравнение без переключения рабочего checkout. Поиск по прошлому содержимому требует отдельного ограниченного обхода ревизий; поиск по сообщениям коммитов его не заменяет.
- Создание, точечная правка или полная замена Markdown, смена Title, Move и добавление вложений используют общий сервис сохранения с Web UI. Читать сохранённую книгу; браузерные несохранённые черновики не считать серверными документами.
- На запись нужны ожидаемые версии затронутых документов; устаревшая версия возвращает конфликт с актуальной версией, без потери чужих изменений. Preview возвращает diff; сохранение повторно проверяет версии. Неизменённый результат не создаёт commit.
- Поддержать согласованный набор правок нескольких файлов одним коммитом: сначала проверить весь набор, затем сохранить целиком. Нужна защита от повторной отправки после сетевого сбоя. Текущий `ProjectbookSave` сохраняет один документ с вложениями; пакетное изменение нескольких документов ещё предстоит реализовать.
- Сейчас блокировка — process-local Mutex в middleware. MCP и Web UI должны разделять одну блокировку проверки/записи; при отдельных процессах понадобится межпроцессный lock. Не считать отдельный MCP-процесс с прямой записью в Git уже согласованным с UI.
- Ответ на успешную запись: изменённые пути, Git commit, новые версии и ссылки для просмотра. Локальный commit не означает push: Git-синхронизация остаётся отдельным этапом.

### Подключение и доступ
- Предпочтительная поставка — endpoint `/mcp` в том же контейнере/приложении с общим сервисом книги. Streamable HTTP подходит для подключения локально и позже через HTTPS. Конкретный SDK/версию протокола выбрать после проверки совместимости клиента; самодельную реализацию протокола не начинать без необходимости.
- Локальный стенд привязан к loopback. Выделить доступ read-only и read-write; credentials вне Git, проверка Origin/Host и границы каталога книги. Удалённый доступ — только после отдельной настройки аутентификации/HTTPS. GitHub-права не становятся автоматически MCP-правами.
- Не давать агенту произвольный shell, файловую систему хоста или автоматический force push. Обработка истории не изменяет checkout. Удаление файлов — отдельная явно названная операция, не побочный эффект индексирования.
